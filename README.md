# MulkCare (mullky) — تطبيق عناية بالعقارات

تطبيق أندرويد (Flutter) لملّاك الفلل والشاليهات في الغردقة. الواجهة عربية RTL، والتصميم مرجعه الوحيد [`DESIGN.md`](DESIGN.md) (انتقال من نموذج React وليس إعادة تصميم).

## الحلقة الأساسية (MVP)
العميل (صاحب العقار) ← الوحدة (فيلا/شاليه) ← طلب خدمة (تنظيف/صيانة/فحص/مكافحة) ← حالة (قيد الانتظار → جاري → مكتمل) ← فاتورة (مدفوعة/غير مدفوعة).

الشاشات الخمس: تسجيل الدخول · الرئيسية (قائمة الوحدات) · تفاصيل الوحدة (السجل والفواتير) · طلب خدمة · الأدمن (داخل التطبيق، بعلامة `is_admin`).

كل ما عدا ذلك مؤجل (المرحلة 2 وما بعدها): دليل المدينة، المساعد الذكي، الاشتراكات، الدفع الأونلاين، موقع/لوحة تحكم، العمال، العملاء الصناعيون.

## الحالة الحالية (Stage 1)
- الشاشات الخمس تعمل على **بيانات تجريبية في الذاكرة** بتسجيل دخول **تجريبي** (أي بريد وكلمة مرور 6 أحرف؛ بريد يبدأ بـ `admin@` = أدمن). الشارة «وضع تجريبي» ظاهرة.
- لم يُربط بعد: Supabase (Auth/Postgres/Storage/RLS)، كاش SQLite والمزامنة، صور الطلبات. انظر [`.agent/implementation.md`](.agent/implementation.md) للحالة الصادقة لكل بند.

## البناء (CI فقط — لا يوجد Flutter محليًا)
- GitHub Actions: `.github/workflows/build-apk.yml` → `flutter analyze` + `flutter test` + `flutter build apk --release`.
- Flutter مثبّت على `3.47.7` (نفس إصدار مشروع manager-assistant-ready الأخضر).
- مجلد `android/` يُولَّد داخل CI ولا يُرفع. معرّف التطبيق `com.mullky` (يُتحقق منه تلقائيًا في CI).
- الـ APK يظهر في Releases (pre-release باسم `build-<رقم>`). **اختبار الجهاز لم يحدث بعد** — نجاح CI لا يعني أن التطبيق يعمل على الهاتف.
