# Mission — 2026-11-01 — MulkCare JavaScript to Flutter

المهمة: إنشاء فرع Flutter مستقل من `main`، والحفاظ على كامل واجهة MulkCare وبياناتها وعلامتها، ثم بناء APK من GitHub Actions دون SDK محلي.

## المراحل

**A — السلامة والفحص.** تم تحديد `main` عند `b428a8d` كقاعدة الفرع، ومراجعة الالتزام/الفرع السابق والـworkflow ومقارنتهما بالشاشات الأصلية. لا يعاد استخدام الفرع السابق أساسًا، ولا يلمس `main`.

**B — الأساس المشترك.** تجهيز نماذج Flutter والحالة والتخزين المحلي والترجمة والخطوط والأصول والثيم، مع تسجيل العقود في `lib/CONTRACT.md`.

**C — الترحيل.** إنشاء إحدى عشرة شاشة منفصلة من المصادر الأصلية، بملفات متخصصة لكل route، مع الحفاظ على المحتوى وسلوك demo وعدم تقليص النطاق إلى خمس شاشات.

**D — الاختبارات والتكامل.** تحليل جميع الشاشات، توحيد المفاتيح والمسارات، كتابة اختبارات الحالة والانتقالات واللغة، ثم تعديل مواضع الخطأ بدل تعطيل الاختبارات.

**E — CI وتسليم APK.** GitHub Actions يولّد Android scaffold، يثبت Flutter `3.47.7`، يشغل `flutter analyze` و`flutter test` و`flutter build apk --release`، ويرفع artifact محدود المدة. لا ينشئ release عامًا ولا ينشر إلى Play.

## قواعد الخروج

الاكتمال يتطلب نجاح التحليل والاختبارات وبناء APK على Actions. لا يُدّعى فحص جهاز Android محلي أو فعلي. أي شاشة غير مكتملة أو مسار غير موصول يُسجل صراحةً قبل التسليم.
