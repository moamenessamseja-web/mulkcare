# `.agent/` — ابدأ من هنا

هذه ملفات التشغيل الحية لمشروع Flutter. اقرأها بهذا الترتيب قبل أي جلسة تطوير، ثم حدّث سجل الحالة والتسليم والجرد بعد كل نتيجة CI مؤكدة:

1. `Implementation_Plan_and_Development_Instructions.md` — الهدف الكامل ومعايير القبول وحدود التغيير.
2. `IMPLEMENTATION_STATE.md` — نقطة الأساس، آخر نتيجة تحقق، والعوائق.
3. `HANDOFF.md` — ما الذي ينبغي فعله بعد ذلك، وعلى أي فرع.
4. `implementation.md` — جرد صريح لكل شاشة وطبقة حسب حالتها الفعلية.
5. `CHANGELOG.md` — تغييرات أُنجزت فعلًا فقط.
6. `mission_2026-11-01.md` — مراحل هذه المهمة وترتيب التنفيذ.
7. `ARCHITECTURE_AUDIT.md` و`VERIFICATION_REPORT.md` — قرارات البنية وأدلة التحقق.
8. `BRIEF.md`, `DECISIONS.md`, `ENGINEERING_RULES.md`, `LESSONS.md` — ملخص المالك، القرارات، قواعد التنفيذ، والدروس المتراكمة.

قاعدة أساسية: نجاح GitHub Actions لا يثبت تجربة الجهاز. لا تُسجّل اختبارًا على جهاز فعلي ما لم يحدث فعلًا. لا تدمج إلى `main`، ولا تغيّر معرّف التطبيق أو التوقيع أو إعداد Play، ولا تحفظ أسرارًا في المستودع.
